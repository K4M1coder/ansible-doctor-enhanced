# Annotation Guide

This guide explains how to use inline annotations in your Ansible roles to enhance documentation generated by ansible-doctor-enhanced.

## Overview

Ansible Doctor Enhanced extracts inline annotations from YAML comments to generate rich documentation. Annotations follow a simple, readable format that doesn't interfere with your Ansible code.

### Supported Annotation Types

| Annotation | Purpose | Location |
|------------|---------|----------|
| `@var` | Document variables | `defaults/`, `vars/` |
| `@todo` | Track pending work | Any YAML file |
| `@example` | Provide code examples | Any YAML file |
| `@tag` | Document task tags | Future feature |
| `@meta` | Additional metadata | Future feature |

## Variable Annotations (@var)

Document variables in `defaults/main.yml` or `vars/main.yml` using the `@var` annotation.

### Basic Format

```yaml
# @var variable_name:description: Human-readable description
# @var variable_name:type: string|number|boolean|list|dict
# @var variable_name:example: "example value"
# @var variable_name:required: true|false
# @var variable_name:deprecated: "Use new_variable instead"
variable_name: default_value
```

### Supported Attributes

- **description**: Human-readable description of the variable's purpose
- **type**: Data type (string, number, boolean, list, dict)
- **example**: Example value showing proper usage
- **required**: Whether the variable must be set by the user
- **deprecated**: Deprecation message with migration guidance

### Examples

#### Simple Variable

```yaml
# @var web_port:description: Port number for the web server
# @var web_port:type: number
# @var web_port:example: 8080
web_port: 80
```

#### Required Variable with Example

```yaml
# @var db_host:description: Database server hostname or IP address
# @var db_host:type: string
# @var db_host:example: "db.example.com"
# @var db_host:required: true
db_host: "localhost"
```

#### Deprecated Variable

```yaml
# @var old_config_path:description: Legacy configuration file path
# @var old_config_path:deprecated: "Use app_config_dir instead"
old_config_path: "/etc/oldapp/config"
```

#### Complex Variable (Dict)

```yaml
# @var app_config:description: Application configuration dictionary
# @var app_config:type: dict
app_config:
  database:
    host: localhost
    port: 5432
  cache:
    enabled: true
    ttl: 3600
```

### Alternative Formats

#### JSON Format (Compact)

```yaml
# $ {"type": "string", "description": "API endpoint URL", "required": true}
api_url: "https://api.example.com"
```

#### Multiline YAML Format

```yaml
# >
# Complex variable description that spans
# multiple lines for better readability
# @end
my_variable: value
```

## TODO Annotations (@todo)

Track pending work, improvements, and known issues using `@todo` annotations.

### Basic Format

```yaml
# @todo: Description of the pending work
# @todo(priority): Description with priority level
```

### Priority Levels

- **critical**: Blocking issues that must be fixed immediately
- **high**: Important improvements or features
- **medium**: Nice-to-have improvements (default)
- **low**: Minor enhancements or cleanup tasks

### Examples

#### Simple TODO

```yaml
---
# Main task file
# @todo: Add input validation for user-provided variables

- name: Configure application
  ansible.builtin.template:
    src: config.j2
    dest: /etc/app/config.yml
```

#### TODO with Priority

```yaml
# @todo(critical): Add error handling for failed service starts
# @todo(high): Implement SSL/TLS certificate validation
# @todo(medium): Add support for custom authentication backends
# @todo(low): Improve logging verbosity options

- name: Start application service
  ansible.builtin.systemd:
    name: myapp
    state: started
```

#### Inline TODO in Tasks

```yaml
- name: Install packages
  ansible.builtin.package:
    name: "{{ item }}"
    state: present
  loop:
    - nginx
    - postgresql
  # @todo(high): Add version pinning for production deployments
```

### TODO Output

Generated documentation includes:

```json
{
  "todos": [
    {
      "description": "Add error handling for failed service starts",
      "file_path": "tasks/main.yml",
      "line_number": 3,
      "priority": "critical"
    }
  ]
}
```

## Example Annotations (@example)

Provide code examples to help users understand variable usage and common patterns.

### Basic Format

#### Single-line Example

```yaml
# @example: variable_name: "example_value"
```

#### Multiline Example

```yaml
# @example Title of the example
# code line 1
# code line 2
# @end
```

### Examples

#### Basic Configuration Example

```yaml
# @example Basic web server configuration
# web_port: 8080
# web_ssl_enabled: false
# web_workers: 4
# @end
web_port: 80
```

#### Advanced Example with Description

```yaml
# @example Production setup with SSL
# web_port: 443
# web_ssl_enabled: true
# web_ssl_cert: "/etc/ssl/certs/server.crt"
# web_ssl_key: "/etc/ssl/private/server.key"
# web_workers: 8
# @end
web_port: 80
```

#### Example in Task Files

```yaml
# @example Running specific tasks with tags
# ansible-playbook site.yml --tags "installation"
# ansible-playbook site.yml --tags "configuration,deployment"
# @end

- name: Install required packages
  ansible.builtin.package:
    name: "{{ item }}"
    state: present
  loop:
    - curl
    - wget
  tags:
    - installation
    - packages
```

### Language Detection

Ansible Doctor Enhanced automatically detects the language of code examples:

- **yaml**: Default for examples in YAML files
- **bash**: Detected from shell commands (ansible-playbook, curl, etc.)
- **python**: Detected from Python code patterns
- **json**: Detected from JSON syntax
- **jinja2**: Detected from Jinja2 template syntax

### Example Output

Generated documentation includes:

```json
{
  "examples": [
    {
      "title": "Basic web server configuration",
      "code": "web_port: 8080\nweb_ssl_enabled: false\nweb_workers: 4",
      "description": null,
      "language": "yaml"
    }
  ]
}
```

## Tag Documentation

Task tags are automatically extracted from your `tasks/*.yml` and `handlers/*.yml` files. No special annotations are needed.

### Tag Extraction

```yaml
- name: Install packages
  ansible.builtin.package:
    name: nginx
    state: present
  tags:
    - installation
    - packages
    - setup

- name: Configure service
  ansible.builtin.template:
    src: config.j2
    dest: /etc/nginx/nginx.conf
  tags:
    - configuration
    - deployment
```

### Tag Output

Generated documentation includes:

```json
{
  "tags": [
    {
      "name": "installation",
      "description": null,
      "usage_count": 3,
      "file_locations": [
        "tasks/main.yml:5",
        "tasks/install.yml:2",
        "tasks/setup.yml:10"
      ]
    }
  ]
}
```

### Tag Usage Statistics

- **usage_count**: Number of tasks using this tag
- **file_locations**: List of file:line references for each usage
- **description**: Optional description (via `@tag` annotation in future versions)

## Best Practices

### General Guidelines

1. **Be Consistent**: Use the same annotation style throughout your role
2. **Be Concise**: Keep descriptions clear and to the point
3. **Be Complete**: Document all user-facing variables
4. **Be Accurate**: Keep annotations up-to-date with code changes

### Variable Documentation

✅ **DO:**
```yaml
# @var db_password:description: Database password for application user
# @var db_password:type: string
# @var db_password:required: true
# @var db_password:example: "SecureP@ssw0rd"
db_password: ""
```

❌ **DON'T:**
```yaml
# Password
db_password: ""
```

### TODO Annotations

✅ **DO:**
```yaml
# @todo(high): Implement connection pooling for database
# @todo(medium): Add retry logic with exponential backoff
```

❌ **DON'T:**
```yaml
# TODO fix this
# needs work
```

### Example Annotations

✅ **DO:**
```yaml
# @example Production deployment with high availability
# db_host: "db-primary.example.com"
# db_port: 5432
# db_replica_hosts:
#   - "db-replica1.example.com"
#   - "db-replica2.example.com"
# db_pool_size: 20
# @end
```

❌ **DON'T:**
```yaml
# Example:
# db_host: localhost
```

### Organization Tips

1. **Group Related Variables**: Keep related variable annotations together
2. **Order by Importance**: Document required variables first
3. **Use Examples Generously**: Provide examples for complex configurations
4. **Track TODOs Actively**: Use priorities to manage technical debt
5. **Update Regularly**: Review and update annotations with code changes

### Template Example

Here's a complete example showing best practices:

```yaml
---
# Application Configuration Variables
# These variables control the core application behavior

# @var app_name:description: Name of the application (used in logs and configs)
# @var app_name:type: string
# @var app_name:required: true
# @var app_name:example: "my-web-app"
app_name: "default-app"

# @var app_port:description: TCP port for the application server
# @var app_port:type: number
# @var app_port:example: 8080
app_port: 8000

# @var app_debug:description: Enable debug logging and verbose output
# @var app_debug:type: boolean
# @var app_debug:example: false
app_debug: false

# @todo(high): Add support for multiple app instances with load balancing
# @todo(medium): Implement health check endpoint configuration

# @example Basic development setup
# app_name: "dev-app"
# app_port: 3000
# app_debug: true
# @end

# @example Production deployment
# app_name: "prod-api"
# app_port: 8443
# app_debug: false
# app_ssl_enabled: true
# app_workers: 4
# @end
```
